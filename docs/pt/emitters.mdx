# Emitters

Os emitters oficiais em prévia ficam no monorepo (`transpilers/`). Todos compartilham um AST validado via `aip parse` / `aip validate`.

A maturidade é rastreada em [`EMITTER_OBJECTIVES.md`](https://github.com/eudameron/aiparlance/blob/main/EMITTER_OBJECTIVES.md) (**55** IDs). Cada pacote tem ficha de maturidade por papel: ✅ Passou · ⚠️ Parcial · ❌ Falhou · ➖ N/A (fora do papel).

**Nota** = ✅ ÷ (55 − ➖).

Cada página de emitter lista os objetivos **✅ Passou**, **⚠️ Parcial** e **❌ Ainda falhando** para leitura rápida (e como re-testar).

## Papéis

| Papel | Significado |
|---|---|
| `schema` | DDL / schema persistente |
| `contract` | Contrato HTTP da API |
| `app` | Tipos de aplicação → API executável |
| `workers` | Jobs / filas / workflows |
| `docs` | Referência legível por humanos |
| `tests` | Fixtures / scaffolds de teste |

Emitters especializados não precisam passar em runtime HTTP — esses itens são ➖ N/A.

## Como os objetivos são testados

1. **Testes automatizados** — Vitest em `transpilers/<nome>/` (+ `scripts/examples.test.ts` no repo).
2. **Checklist manual** — Conferir o emit contra cada ID aplicável no [`EMITTER_OBJECTIVES.md`](https://github.com/eudameron/aiparlance/blob/main/EMITTER_OBJECTIVES.md) do pacote.
3. **Caminho feliz (Phase D)** — Critérios HP1–HP10 com TS + OpenAPI + SQL em `examples/blog-crud.aip`.

```bash
npm test
node packages/cli/dist/cli.js emit <target> examples/minimal.aip
node packages/cli/dist/cli.js emit <target> examples/blog-crud.aip
```

Checklist canônico: [EMITTER_OBJECTIVES.md](https://github.com/eudameron/aiparlance/blob/main/EMITTER_OBJECTIVES.md) · Roadmap: [Phase D](https://github.com/eudameron/aiparlance/blob/main/ROADMAP.md).
